# Lore Harvest v0.1.2 Procedural Validation Invariants

JSON Schema Draft 2020-12 validates record structure and many cross-field constraints. The following rules require deterministic Liber Harvest validation because standard JSON Schema cannot fully express cryptographic, referential, ordering, file-level, or semantic comparisons.

## LF-13 — provenance materialization

- Resolve every `json_pointer` against the declared source and require the target to exist.
- `source_span.end > source_span.start`.
- `source_span.text_sha256` equals SHA-256 of exactly `pointer_value[start:end]` with no normalization.
- `anchor_sha256` equals SHA-256 of the complete JSON-pointer target with no normalization.
- The extraction model never invents offsets or hashes.
- Exact excerpt search with one occurrence materializes a span.
- Multiple exact occurrences flag `provenance_span_ambiguous`.
- No exact occurrence flags `provenance_excerpt_unresolved`.
- Field/item precision must have `source_span: null`.

## Provenance identity and ordering

- Every fragment has exactly one `role=primary` anchor. The JSON Schemas also enforce this structurally.
- The primary anchor is serialized first; supporting and duplicate anchors follow in source-evidence order.
- Every provenance `source_path` and `source_sha256` must identify the same source as the containing harvest run unless the future contract explicitly introduces multi-source fragments.
- `source_item_id` and `bundle_id`, when non-null, are historical provenance only and are never used as the sole identity anchor.

## LF-14 — derivation

- Operation-array order is semantically significant and must survive serialization unchanged.
- `direct` is exclusive.
- `primary_mode` must occur in `operations`.
- `merged_intra_source` requires multiple provenance anchors.

## LF-15 — modality

- `claim.modality` may not be stronger than the supporting provenance permits.
- `ambiguous` requires review.
- Normalized prose must visibly preserve non-assertive modality.
- Generated-hook evidence does not become an asserted historical fact merely because the hook prose is declarative.

## LF-16 — evidence layer

- Evidence layer is determined from the semantic origin of the evidence, not merely from Exegate Circle.
- Mixed raw fields may produce different evidence layers at different spans.
- `metadata` evidence alone must not promote generic phase/texture/intensity metadata into asserted lore.

## Materialized fragment identity

- `fragment_id` type code must agree with `type` (also enforced structurally).
- Fragment IDs are generated by Liber Harvest from deterministic identity material, never by the extraction model.
- Re-running materialization with identical identity material must yield the identical `fragment_id`.

## Relation records

- `source_fragment_id` and `target_fragment_id` must resolve to materialized records in the Lore Library.
- Relation endpoints must not silently substitute concept keys for fragment IDs.
- `evidence_fragment_ids` must resolve to materialized fragments.
- Relation IDs should be generated deterministically from relation schema version, relation type, source fragment ID, and target fragment ID.
- Duplicate relation records with identical deterministic identity must be rejected or coalesced deterministically.

## Harvest result and source coverage

- Every non-empty primary Exegate area receives coverage.
- Coverage may use narrow sub-pointers in addition to the required primary-area coverage.
- A `pipeline_wrapper` discard must not suppress embedded lore that was independently extracted.
- `discarded` must never use canon conflict, obsolescence, abandoned storyline, or aesthetic judgment as a reason.

## Manifest and JSONL file integrity

- `manifest.source` must match the materialized source identity.
- Every fragment `harvest.run_id` must equal the containing manifest `run_id`.
- Manifest `counts.fragments` equals the number of non-empty JSONL records.
- Manifest `counts.review_required` equals the number of fragments with `review.required=true`.
- Manifest `counts.warnings` equals the warnings array length.
- Manifest artifact SHA-256 values equal the exact bytes of the referenced files.
- Manifest `artifacts.fragments_jsonl.records` equals the JSONL record count.

## JSONL

- One non-empty line equals one complete JSON object.
- No JSON array wrapper.
- UTF-8 encoding.
- Recommended strict mode rejects blank lines.
- Validation errors report JSONL line number plus JSON Schema instance path.
- Date-time validation must use a validator with JSON Schema format checking enabled.
